# 伦理委员会（Ethics Committee）

包含《三角机构》「伦理委员会」扩展的 TRPG 轨道记录网站。玩家可通过电脑或手机点击格子记录游戏进程，使用自己的账号保存和同步数据。

## 已实现的功能

- **账号自助使用**：邮箱与密码注册、密码重复确认、邮箱验证、重发验证邮件和邮件找回密码。
- **四条独立轨道**：职能、现实、异常各 30 格，人伦条 15 格，每行 10 格；保留格内编号、职能职级与游戏说明。
- **每个账号一份个人记录**：其他玩家无法查看或修改你的进度。
- **自动保存与同步**：每次点格后保存，打开或切回页面时读取最新记录；其他设备先保存时，载入最新状态并提示重新操作。
- **电脑与手机操作**：适配不同屏幕，提供页面内使用说明、保存状态及错误提示。

## 点击格子的规则

每条轨道按从左到右、从上到下的顺序连续排列，初始全空白，只能操作边界格。

- **从左端点亮。** 点击最左侧空白格，变成对应轨道的亮色。点击最后一个已点亮格，可撤回为空白。
- **从右端划去。** 点击最右侧空白格，使它变灰。点击第一个灰格，可撤回为空白。
- **只剩一格空白时**，点击后选择点亮或变灰。其余合法操作点击即生效。

四条轨道各自独立，游戏中的联动效果由玩家手动操作。每次变化会自动保存，打开或切回页面时读取最新记录。若其他设备已保存更新，网页会载入最新状态并提示玩家重新操作。

## 开始使用

1. 打开公开版，使用能接收邮件的邮箱注册，打开验证邮件并在网页中点击「继续」。
2. 登录后点击合法的边界格，等待「已保存」。换设备时使用同一账号登录，读取同一份记录。
3. 忘记密码时，在登录窗口选择「忘记密码？」，打开最新的重置邮件并设置新密码；原有记录会保留。

收不到验证邮件时，可检查垃圾邮件并使用「重发验证邮件」。过期或已使用的链接需要重新发送。若保存结果未确认，先点击「刷新记录」核对云端状态，再继续操作。详细步骤见 [玩家使用说明](PLAYER-GUIDE.md)。

## 本地开发

需要 Node.js 24、pnpm 11.25.0、Python 3.10 或更新版本，以及 Git。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

本地开发默认提供页面内试用，刷新后清空。联网开发可复制 `.env.example` 为 `.env.local`，填写自己 Supabase 项目的 URL 和浏览器发布密钥。

提交前运行检查和生产构建。

```sh
python scripts/verify.py
pnpm test
pnpm build
```

账号请求的自动测试使用测试响应，真实收信和手机流程另有实测记录。数据库结构与权限规则位于 [supabase/migrations](supabase/migrations)。

## 部署

前端使用 Vite 和原生 JavaScript，网站托管在 GitHub Pages，账号与玩家记录由 Supabase Auth 和 PostgreSQL 提供，邮件通过自定义 SMTP 发送。生产配置中的 URL 和 publishable key 用于浏览器连接服务，记录权限由数据库访问规则控制。

第一版的 `main` 分支更新后，`Deploy website` 工作流会验证、构建并发布原网站。本分支只提交到功能分支，且部署工作流限制为 `main` 才能运行，防止手动从功能分支覆盖原站。

公开版使用单独的 Pages 仓库，只发布构建文件，保留现有 `/ethics-committee-preview/` 入口。Supabase 项目与第一版不同，构建配置会拒绝公开版连接第一版的后台。部署的 `version.json` 记录版本号和对应源码提交，GitHub Release 从功能分支的提交建立版本标签。

使用自己的部署时，请配置自己的 Supabase 项目、访问规则及站点地址。邮箱注册需要自定义 SMTP，并使用 [邮件模板](supabase/templates) 中的确认和重置模板，让邮件可以在另一台设备打开。服务端密钥由维护者在服务端管理。
